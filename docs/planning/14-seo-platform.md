# 14. SEO-платформа и объединение программ

Дата: 19.11.2026 · Статус: предложение к D-035 · Связано: D-019, D-033, D-034, ADR-0005

## 1. Контекст и решение

Основатель планирует основной трафик из поисковиков: на домене будет **большой кластер
SEO-статей** по психологическим темам, а продукт — не только «пережить расставание», но позже
тревога, выгорание и другие направления. Расстаются немногие, тревожатся и выгорают — многие,
поэтому воронка должна начинаться с контента по широким темам и вести в подходящую программу.

**Решение (предлагается):**
1. Один бренд, один сайт, одно приложение, **много программ** — «Опора» как платформа
   психологической самопомощи, а не набор отдельных продуктов.
2. Домен = **контент-хаб + продуктовые страницы**:
   SEO-статьи ловят широкий спрос → программа ловит узкий запрос → онбординг и первый день
   бесплатно → покупка программы.
3. Архитектуру закладываем сейчас (маршруты, шаблоны, контент-модель, sitemap, разметка), а
   производство контента запускаем параллельно с T-101/T-102, не дожидаясь полной оплаты (T-104):
   SEO индексируется месяцами, поэтому старт контента — часть продуктового плана, а не «после».

Это **уточняет D-019**: продукт по-прежнему первичен, реклама/Директ — после готовности, но
SEO-контент перестаёт быть «после всего» и становится основным каналом привлечения.

## 2. Продуктовая модель: одна платформа, много программ

### Что такое «программа»

7-дневный модуль с одной темой: уроки, практики, дневник, поддержка AI, финальный отчёт.
Расставание — первый модуль. Тревога, выгорание, самооценка, отношения с собой — следующие.

### Почему не отдельные продукты

| Отдельные продукты/сайты | Одна платформа |
|---|---|
| разные аккаунты, оплаты, поддержка, safety | один аккаунт, одна оплата, общий safety-контур |
| дублирование chat/diary/LLM/модерации | общие движки: чат, дневник, программы |
| нельзя перейти из одной темы в другую | кросс-продажи: закончил расставание → тревога |
| SEO-страницы конкурируют и размывают бренд | один домен накапливает авторитет, кластеры связаны |
| операционно дороже | один продукт с библиотекой программ |

### Пользовательский путь

`статья в поиске → программа (лендинг) → онбординг (что происходит) → рекомендация программы →
первый день бесплатно → оплата 990 ₽ за программу → /app «Сегодня» → по желанию другая программа`.

- **Онбординг** спрашивает «что сейчас происходит» и рекомендует программу, но не запирает:
  в `/app` можно выбрать другую программу.
- **Общее ядро:** дневник, AI-поддержка, safety, профиль, настройки приватности — общие для всех
  программ. Программа задаёт контекст (тема, уроки, промпты, практики).
- **Entitlements:** первый день любой программы бесплатно; 990 ₽ — доступ к конкретной программе
  навсегда; позже подписка 490 ₽/мес открывает библиотеку программ. Без двойных списаний и
  «случайных» продлений; напоминание до списания, отмена в 2 клика.
- **Данные:** одна запись пользователя, отдельные `program_enrollments`; прогресс и ответы
  привязаны к программе; удаление аккаунта удаляет всё.

### Модель данных (эскиз, для T-303)

```
programs(id, slug, title, short_description, status, order)
program_lessons(id, program_id, day, title, body, practice, created_at)
program_enrollments(id, user_id, program_id, started_at, completed_at, status)
program_day_progress(id, enrollment_id, day, completed_at, reflection)
onboarding_answers.focus → programs.pain_tags (mapping)
```

`chat` и `diary` получают `program_id`/`enrollment_id` как контекст; safety-правила — общие.

## 3. Информационная архитектура и URL

### Целевая структура

| URL | Назначение | Индексация |
|---|---|---|
| `/` | бренд-хаб: что такое «Опора», направления, как устроено, доверие, свежие статьи | index |
| `/programs` | каталог программ | index |
| `/programs/rasstavanie` | продающая страница программы «Пережить расставание» | index, canonical |
| `/programs/trevoga`, `/programs/vygoranie` … | то же для новых программ | index |
| `/articles` | хаб статей, рубрики | index |
| `/articles/<cluster>/<slug>` | SEO-статья | index |
| `/articles/<cluster>` | рубрика/кластер | index |
| `/app/**` | продукт (после онбординга) | noindex |
| `/auth`, `/onboarding` | вход/онбординг | noindex |
| `/legal/**` | документы | index |

**Сейчас** `/` — продающая страница «Расставания» (быстрый запуск). **При появлении второй
программы** `/` становится бренд-хабом, а страница расставания переезжает на
`/programs/rasstavanie` с 301-редиректом. Триггер — второй модуль в проде; до этого дублей нет.

### Маршруты в коде (сейчас)

- `apps/web/src/content/programs/rasstavanie.ts` — контент программы, `ProgramContent`.
- `apps/web/src/components/landing/*` — шаблон продающей страницы, принимает `program` пропсом.
- `/sitemap.xml`, `/robots.txt`, metadata, JSON-LD (FAQ/Product) — уже добавлены.
- Следующий шаг: вынести лендинг в `app/programs/[slug]/page.tsx` + `generateMetadata` и
  `generateStaticParams`, оставить `/` как hub-страницу (T-302).

## 4. SEO-стратегия

### Кластеры (спрос → программа)

| Кластер | Примеры запросов (интент) | Программа | Приоритет |
|---|---|---|---|
| Расставание | «как пережить расставание», «не могу забыть бывшего», «хочу написать ему» | Расставание | 1 (запуск) |
| Тревога | «постоянная тревога», «тревожные мысли», «как успокоиться» | Тревога | 2 |
| Выгорание | «выгорание на работе», «нет сил», «эмоциональное истощение» | Выгорание | 2 |
| Самооценка | «не уверена в себе», «сравниваю себя с другими» | Самооценка | 3 |
| Отношения с собой/близкими | «границы в отношениях», «токсичные отношения» | Отношения | 3 |
| Сон/рутина | «не могу уснуть из-за мыслей», «как вернуть режим» | межпрограммный, ведёт в дневник | 3 |

Статья не должна обещать лечение и не подменяет продукт: её задача — ответить на вопрос, дать
один применимый шаг и предложить программу как продолжение.

### Типы контента

1. **Информационные статьи** (основной объём): «Почему после расставания тянет проверять соцсети»
   — объяснение + 1–3 практики + CTA в программу.
2. **How-to/чек-листы:** «Что делать сегодня, если накрыло» — практический сценарий.
3. **Разборы ситуаций/истории** (без ПДн): «Как я проживала первые недели» — только с согласия и
   редакторской обработкой, без обещаний результата.
4. **Справочные/словарные:** «Что такое эмоциональное выгорание» — база для внутренних ссылок.
5. **Сервисные страницы программ** — продающие, не статьи.

### E-E-A-T и YMYL (Яндекс и Google)

Тема психологии — чувствительная (YMYL). Нужны: автор-эксперт (психолог с образованием/практикой),
научный редактор/ревьюер, дата публикации и обновления, ссылки на источники (исследования, ВОЗ,
официальные рекомендации), редакционная политика, дисклеймер «не медицина», прозрачные ограничения.
Не публиковать «терапию»/диагнозы, не обещать результат. AI-тексты — только черновик, финальный
текст проходит человека и профильного ревьюера.

### Техническое SEO

- SSG/ISR для статей и программных страниц; `generateStaticParams`; статический HTML без клиентского
  JS на чтении (острова интерактивности только в CTA).
- `Metadata` на каждую страницу: title ≤ 60, description 120–160, canonical, OG-изображение 1200×630.
- Структурированные данные: `Article`, `BreadcrumbList`, `FAQPage`, `Product`/`Offer` на программах;
  `Organization`, `WebSite` (SearchAction) — на хабе.
- sitemap.xml с разбивкой по разделам (при росте — sitemap-индекс), robots.txt (готово).
- Внутренние ссылки: статья → 2–3 статьи кластера + 1–2 программы; программа → 3–5 статей;
  хлебные крошки; без «сирот».
- Производительность: LCP < 2.5 s на мобильном, без тяжёлых шрифтов/скриптов; фото — WebP,
  `srcset` (уже сделано), шрифты self-hosted с `font-display: swap`.
- Yandex-first: `Яндекс.Вебмастер`, оригинальные тексты, структура и микроразметка, быстрый ответ
  в первом экране, регион РФ; Google Search Console — второй приоритет.
- `noindex` для `/app/**`, `/auth/**`, `/onboarding/**`, `/api/**`; ссылки на них — nofollow где уместно.

### Внутренняя перелинковка (пример)

`/articles/rasstavanie/pochemu-tyanet-proveryat` → CTA-блок «7 дней, чтобы вернуть опору» →
`/programs/rasstavanie` → `/onboarding`; в статье — ссылки на «как перестать писать бывшему» и
«первые недели после разрыва». Программная страница — на 5–8 статей кластера и на FAQ.

## 5. Шаблоны страниц

### Продающая страница программы (уже есть v3)

Hero с фото и продуктом → узнавание боли → как выглядит день → 7 дней → что внутри → безопасность
→ цена и возврат → FAQ → финальный CTA. Шаблон `ProgramContent` — новый модуль = новый файл
контента + маршрут, без копирования вёрстки.

### Статья (T-301)

Хлебные крошки → H1 с ключевым запросом → лид (ответ в первых 2–3 строках) → автор и дата обновления
→ содержание (TOC) → текст с подзаголовками H2/H3 → практика/чек-лист → CTA-блок «Попробовать
программу» → источники → дисклеймер → связанные статьи. Оформление: `paper-read` фон, Literata для
чтения, Onest для заголовков, ширина 58–68 знаков, без карточек-«близнецов».

### Хаб и рубрики

`/` — бренд-хаб с программами и свежими статьями; `/articles` — поиск/рубрики; рубрика — список
статей + CTA программы; пагинация и canonical.

## 6. Контент-модель и реализация

- **Программы:** TypeScript-объекты `ProgramContent` (уже). Плюс `programs` в БД для прогресса
  (T-303).
- **Статьи (фаза 2):** MDX-файлы `apps/web/src/content/articles/<cluster>/<slug>.mdx` с frontmatter
  (`title`, `description`, `cluster`, `publishedAt`, `updatedAt`, `author`, `reviewer`, `sources`,
  `relatedProgram`, `ogImage`). Рендер на сервере, SSG, `generateStaticParams`, `generateMetadata`.
  CMS (Contentful/Strapi/своя админка) — только когда контента > 100 статей или нужен нетехнический
  редактор; до этого MDX + git-ревью быстрее и надёжнее.
- **Изображения:** WebP + `srcset`, gen-OG 1200×630 из шаблона, alt-тексты по правилам дизайна.
- **Поиск по сайту:** позже, после 50+ статей (лёгкий клиентский или серверный).
- **Аналитика:** Яндекс.Метрика + серверные события воронки; UTM/кластер в первом касании;
  события: `article_view`, `program_cta_click`, `onboarding_start`, `first_day_complete`,
  `paywall_view`, `purchase` (позже). Без ПДн в событиях.

## 7. Метрики

| Этап | Метрика |
|---|---|
| Привлечение | органические сессии по кластерам, доля новых, показы/CTR в Вебмастере |
| Переход в продукт | CTR CTA «программа» со статей, конверсия статьи → онбординг |
| Продукт | завершение онбординга, первый день бесплатно, дочитывание 7 дней |
| Деньги | конверсия онбординг → оплата, ARPPU, возвраты, LTV (позже) |
| Качество | глубина/время на статье, отказы, жалобы, возвраты |

Целевые ориентиры на MVP: 50–100 статей в первых 3 кластерах, 10–20% статей дают 80% трафика,
конверсия статья → онбординг 2–5% (проверять), онбординг → покупка 3–7% (проверять).

## 8. Риски и ограничения

1. **Юридические:** никакой медицины, диагнозов, обещаний; психологические данные — спец. категория
   (152-ФЗ); отзывы — только с согласием; статьи не собирают ПДн; дисклеймеры обязательны.
2. **E-E-A-T:** без эксперта-ревьюера контент не ранжируется устойчиво; нужен психолог-редактор.
3. **Качество против объёма:** 500 слабых статей хуже 50 сильных; приоритет — кластеры с продуктом.
4. **Каннибализация:** одна статья = один интент; карта кластера и перелинковка.
5. **Домен молодой:** SEO — 6–12 месяцев; параллельно продукт и удержание, не только трафик.
6. **AI-контент:** поисковики и аудитория распознают; только черновики + человеческая редактура +
   экспертное ревью.
7. **Операционка:** контент-план, ревью, обновления, аналитика — это регулярный процесс; без него
   кластер умирает.

## 10. Открытые вопросы

1. Стартовая модель: 990 ₽ за программу, потом подписка 490 ₽/мес на все — или сразу подписка?
2. Кто психолог-ревьюер и автор (нужен для E-E-A-T и юридической безопасности контента)?
3. Язык/тон статей: «ты» и разговорный, как на лендинге, или нейтральнее для SEO?
4. Какие 2 кластера после расставания: тревога и выгорание — или тревога и самооценка?
5. Нужен ли бесплатный инструмент (чек-лист/тест) как lead magnet для сбора почты до продукта?
