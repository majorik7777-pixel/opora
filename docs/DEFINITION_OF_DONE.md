# Definition of Done — что считается готовой задачей

Версия 1.0 · 19.11.2026

Задача не считается выполненной, пока не пройден весь чек-лист, относящийся к её типу. Статус `done` ставит основатель/лид после приёмки — агент сдаёт задачу в `review` (см. [`tasks/README.md`](../tasks/README.md)). Код без тестов, документации и обновлённой задачи не принимается.

Основа: `docs/planning/07-architecture.md §1.4`, `docs/planning/12-tech-plan.md §14`, `AGENTS.md §11`.

---

## 1. Код и проверки

- [ ] `pnpm lint` проходит без ошибок и предупреждений.
- [ ] Типы: `pnpm typecheck` проходит без ошибок (весь workspace).
- [ ] `pnpm test` проходит: новые/изменённые unit- или integration-тесты есть и покрывают поведение, а не только «код компилируется».
- [ ] `pnpm build` проходит (production-сборка Next.js).
- [ ] `pnpm verify` прогнан целиком (lint + typecheck + test + build).
- [ ] Для UI-путей — `pnpm test:e2e` проходит (или сценарий добавлен и проходит локально; CI проверяет то же самое).
- [ ] Если менялась схема БД — миграция добавлена в runtime-раннер `packages/db/src/migrations.ts` (или сгенерирована `pnpm db:generate` и перенесена), применяется с нуля (`AUTO_MIGRATE=true` в dev/e2e) и не ломает существующие данные.
- [ ] Нет `any`, `@ts-ignore`, отключённого линта и закомментированного кода «на потом» без задачи. Временные обходы зафиксированы в задаче.

## 2. Данные, приватность, безопасность

- [ ] Новые чувствительные поля зашифрованы на уровне приложения (AES-256-GCM через `@opora/shared/server`).
- [ ] ПДн (персональные данные) не попадают в логи, телеметрию, Sentry/аналитику, сообщения об ошибках и тестовые артефакты.
- [ ] Доступ проверяется на сервере: пользователь видит только свои данные; неавторизованный запрос редиректит на вход или возвращает `AUTH_REQUIRED`.
- [ ] Согласия и 18+ соблюдены: без них нет сохранения психологических данных; при изменении юридических текстов обновлена версия (`CONSENT_VERSION`).
- [ ] Секреты не в коде и не в git; новые переменные окружения добавлены в `.env.example` (без значений) и в `docs` при необходимости.
- [ ] Внешний сервис (LLM, платежи, почта, файлы) — только за адаптером; домены не импортируют его SDK.

## 3. UI и тексты

- [ ] Мобильный вид проверен на **360 px**: нет горизонтального скролла, кнопки не обрезаны, читаемо.
- [ ] Доступность: контраст AA, видимый фокус, тач-зоны ≥ 44 px, формы с подписями и текстовыми ошибками, `prefers-reduced-motion` учтён.
- [ ] Есть состояния: пустое (empty), загрузка (loading/skeleton), ошибка (error), disabled/hover/focus — по необходимости.
- [ ] Тексты — русские, тон тёплый и взрослый, обращение «ты», без медицинских формулировок и обещаний результата, без давления и чувства вины.
- [ ] Дисклеймер «не медицинская услуга» и 18+ — там, где нужны (лендинг, онбординг, юридические страницы; позже — чат, программа, отчёт).
- [ ] Дизайн — по `10-design.md`: токены, типографика, радиусы; никаких стоковых фото людей, маскотов и тёмных паттернов.

## 4. Документация и процесс

- [ ] Файл задачи `tasks/<id>.md` обновлён: статус `review`, что сделано, какие файлы затронуты, какие проверки прогнаны, допущения и открытые вопросы.
- [ ] `tasks/README.md` / индекс задач не требует ручной правки (если требует — правка сделана).
- [ ] При архитектурном решении добавлен ADR в `docs/adr/` (формат — как в существующих ADR).
- [ ] При изменении решения добавлена запись `D-XXX` в `docs/planning/06-decision-log.md` (делает интегратор; агент предлагает формулировку в задаче).
- [ ] Обновлены затронутые документы: `docs/specs/*`, `docs/prd.md`, `README.md`, `AGENTS.md`, runbook — если задача меняет описанное там поведение.
- [ ] Ссылки в добавленных документах относительные и рабочие; даты и версии актуальны.

## 5. Приёмка

- [ ] Все acceptance-критерии задачи выполнены и отмечены в файле задачи.
- [ ] Изменения просмотрены вторым агентом или основателем; замечания закрыты или вынесены в новую задачу.
- [ ] Нет незакоммиченных секретов, `.env`, `.data/`, `node_modules/` и артефактов тестов.
- [ ] После приёмки основатель/лид ставит `done`; при возврате — статус снова `in_progress` с комментарием, что исправить.

## 6. Что не является «готово»

- «Работает у меня локально» без `pnpm verify` и e2e для UI-пути.
- Функция без пустого/ошибочного состояния и без мобильной проверки.
- Задача, где текст переписки/дневника попал в лог «для отладки».
- Задача, где решение принято, но не зафиксировано в `06-decision-log.md`/ADR.
- Задача со статусом `done`, поставленным самим исполнителем.
