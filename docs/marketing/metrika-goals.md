# Яндекс.Метрика: счётчик и цели

Счётчик: **114384853** · Домен: `opora-psihologii.ru` · Включено: `ssr`, `webvisor`, `clickmap`,
`accurateTrackBounce`, `trackLinks`, `ecommerce: dataLayer`.

Код: [`apps/web/src/components/analytics/yandex-metrika.tsx`](../../apps/web/src/components/analytics/yandex-metrika.tsx).
Номер счётчика задаётся переменной окружения `NEXT_PUBLIC_YM_ID` **на этапе сборки** (иначе компонент
молча выключен). На тестовом сервере — `NEXT_PUBLIC_YM_ID=114384853`.

## Два способа считать цель

1. **JS-событие** (`reachGoal`) — точнее по смыслу и параметрам, но не срабатывает при блокировщике.
2. **Отдельная страница** (цель «Посещение страницы») — работает всегда, потому что это просто заход
   на URL. Для ключевых конверсий используем оба пути: событие + страница успеха.

Поэтому регистрация теперь заканчивается страницей **`/welcome`** (после подтверждения magic-link),
а не сразу `/app`: даже с AdBlock визит `/welcome` засчитается.

## События в коде (создать в Метрике как «JavaScript-событие»)

| Цель | Где срабатывает | Смысл |
|---|---|---|
| `cta_hero` | кнопка в первом экране лендинга | клик по главному офферу |
| `cta_header` | кнопка в шапке | клик из навигации |
| `cta_price` | кнопка в блоке цены | решение у цены |
| `cta_final` | кнопка в финальном блоке | «дожал» до конца страницы |
| `cta_sticky` | мобильная липкая кнопка | мобильный сценарий |
| `onboarding_complete` | после ответа на 5 вопросов и согласия | дошла до конца онбординга |
| `chat_message` | успешный ответ в чате | чат реально работает |
| `chat_limit` | попытка 6-го сообщения | упёрлась в лимит 5/день |
| `chat_crisis` | кризисное сообщение | safety-срабатывание (не для оптимизации, для контроля) |
| `safety_call` | клик по телефону на `/app/safety` | человек реально звонит |
| `welcome_to_app` | с `/welcome` в приложение | дошла до продукта |

## Цели по URL (создать как «Посещение страницы»)

| Условие | Смысл |
|---|---|
| `url: содержит /welcome` | **регистрация завершена** (главная цель воронки) |
| `url: содержит /onboarding` | вход в онбординг (аналог `cta_*`, но без JS) |
| `url: содержит /app` | первый вход в продукт |
| `url: содержит /legal/offer` | интерес к условиям перед оплатой |

## Воронка, которую смотрим

`визит → cta_* → /onboarding → onboarding_complete → /welcome (регистрация) → chat_message или /app →
paywall (T-104) → оплата`

Метрики по дням: CR лендинг→онбординг, CR онбординг→регистрация, доля дошедших до чата,
доля упёршихся в лимит (`chat_limit` — сигнал, что пора продавать программу).

## Что проверить руками после деплоя

1. Открыть сайт с обычным браузером → в Метрике «Сводка» появился визит с `opora-psihologii.ru`.
2. Клик по кнопке первого экрана → в «Целях» выросло `cta_hero`.
3. Пройти онбординг и вход → визит `/welcome` и событие `onboarding_complete`.
4. Отправить сообщение в чате → `chat_message`.
5. Включить блокировщик → JS-событий нет, но `/welcome` всё равно засчитан.

## Приватность

Вебвизор включён: на тестовом контуре данные синтетические, реальных переписок быть не должно.
Перед публичным запуском решить: оставлять ли вебвизор для страниц `/app/*` (там чувствительный
текст). Рекомендация — отключить вебвизор на `/app` через `ym(..., 'params')`/исключения в настройках
счётчика и не отправлять в события текст сообщений (сейчас отправляются только имена целей).
