# ADR-0004. Внешний OpenAI-совместимый LLM-провайдер для тестов и первой работы

Дата: 19.11.2026 · Статус: принято (временное решение до production-провайдера РФ)

## Контекст

Основатель хочет проходить и тестировать продукты чата/поддержки на внешнем провайдере уже сейчас, а production-контур РФ (YandexGPT / GigaChat) подключить позже (D-021, D-010). При этом психологические данные — специальная категория ПДн, и отправлять реальные переписки за рубеж нельзя (08-legal-pdn.md, D-010, D-023).

## Решение

В адаптер `@opora/llm` добавлен провайдер `openai-compatible`: любой HTTP API с OpenAI-совместимым протоколом (`/chat/completions` со SSE-стримингом, `/embeddings`) — OpenRouter, OpenAI, DeepSeek, Groq, локальный vLLM/Ollama. Конфигурация — только через env:

```
LLM_PROVIDER=openai-compatible
LLM_BASE_URL=https://openrouter.ai/api/v1
LLM_MODEL=<id модели>
LLM_API_KEY=<ключ>
```

Провайдер выбирается фабрикой `createLlmProvider(kind, config)`; домены SDK не импортируют (границы ADR-0001). Кризисная классификация в этом провайдере — локальные regex-правила `moderateText`, без вызова внешнего `/moderations`.

## Ограничения и условия

- **Только синтетические/тестовые данные.** Реальные переписки и записи дневника (спец. категория ПДн) не отправляются внешнему API: это трансграничная передача (ст. 12 152-ФЗ, D-010/D-023). До production-провайдера в РФ чат работает в тестовом режиме на синтетике.
- Ключ — только в корневом `.env`, не в репозитории; `.env.example` содержит пустые значения.
- Для production остаётся требование T-101: провайдер, обрабатывающий данные в РФ, договор поручения (D-010, D-023).

## Альтернативы

- **Дождаться российского провайдера** — блокирует проверку продукта и сценариев.
- **Свой шлюз/посредник** — не решает трансграничку (D-023), лишняя инфраструктура.
- **Только fake** — не проверяет реальное качество ответов.

## Следствия

- Тестовые прогоны чата можно вести через OpenRouter/аналог, переключая провайдера env-переменными.
- При появлении ключей Яндекса/GigaChat добавляется соответствующая реализация в `packages/llm` (T-101), без изменения доменов.
- В интерфейсе/логах не логируется текст запросов и ключи; для e2e остаётся `fake`.
