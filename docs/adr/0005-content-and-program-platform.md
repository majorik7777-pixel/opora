# ADR-0005. Контент-платформа и объединение программ

Дата: 19.11.2026 · Статус: предложено (ожидает D-035) · Связано: D-019, D-033, D-034

## Контекст

Основной канал привлечения — органический поиск. На домене планируется большой кластер
SEO-статей по психологическим темам; продукт будет расширяться с «пережить расставание» на
тревогу, выгорание и другие направления. Нужно решить архитектуру сейчас, чтобы не переделывать
URL, данные и приложение при росте.

## Решение

1. **Одна платформа, много программ.** Бренд «Опора», один сайт, одно приложение, один аккаунт,
   общие чат/дневник/safety. «Программа» — 7-дневный модуль; тема задаёт контент и контекст, но не
   создаёт отдельный продукт. Новые направления добавляются как программы, а не как новые сервисы.
2. **Домен = контент-хаб + программа-страницы.** Статьи ловят широкий спрос, страницы программ —
   узкий; воронка: статья → программа → онбординг → первый день бесплатно → покупка.
3. **URL-схема:** `/`, `/programs/[slug]`, `/articles/[cluster]/[slug]`, `/app/**` (noindex).
   Пока `/` — продающая страница «Расставания»; при второй программе `/` становится хабом, а
   страница программы переезжает на `/programs/rasstavanie` с 301.
4. **Контент-модель:** программы — типизированные TS-объекты (`ProgramContent`) сейчас, таблицы БД
   для прогресса — T-303; статьи — MDX с frontmatter (SSG/ISR), CMS — только при масштабе > 100
   статей. Человеческая редактура и психолог-ревьюер обязательны (YMYL/E-E-A-T).
5. **SEO-технический слой:** sitemap, robots, canonical, OG, JSON-LD (Article/FAQ/Product),
   хлебные крошки, внутренняя перелинковка, производительность, Яндекс-первый.
6. **Аналитика:** события воронки без ПДн (Яндекс.Метрика + серверные события), UTM/кластер.

## Альтернативы

- **Отдельные продукты/сайты под каждую тему** — отклонено: дублирование, разные аккаунты и
  оплаты, конкуренция страниц, операционная сложность.
- **Ждать полного продукта и только потом SEO** — отклонено: SEO индексируется месяцами; контент
  запускается параллельно с продуктом, реклама — после готовности (D-019 сохраняется в этой части).
- **Один общий лендинг без программ** — отклонено: нельзя точечно объяснять пользу под запрос и
  масштабировать на новые темы; теряется релевантность.
- **CMS сразу** — отклонено на старте: медленнее и дороже, чем MDX + git-ревью.

## Следствия

- Лендинг должен быть шаблоном (`ProgramContent`), а не одной страницей: T-302.
- Нужны миграции и доменные функции для программ/зачислений/прогресса: T-303.
- Нужен контент-процесс и роли (автор, психолог-ревьюер, редактор): T-304.
- Нужны SEO-маршруты, шаблон статьи, разметка и аналитика: T-301, T-305.
- Планировочный документ: `docs/planning/14-seo-platform.md`.
