# Смоук-тест LLM: OpenCode Go → DeepSeek V4.1 Flash

Дата: 19.11.2026 · Статус: провайдер работает · Только синтетические данные

## Конфигурация

| Параметр | Значение |
|---|---|
| Провайдер | OpenCode Console / Go (OpenAI-совместимый шлюз) |
| Base URL | `https://opencode.ai/inference/go/openai/v1` |
| Модель | `deepseek-v4.1-flash` |
| Ключ | `oc_sk_...` — только в корневом `.env` (chmod 600), в репозиторий не попадает |
| Адаптер | `@opora/llm` → `createLlmProvider("openai-compatible", …)` |
| Заголовки | `Authorization: Bearer`, `x-opencode-session: ses_<uuid>`, `User-Agent: opora-app/0.1` |

Go-эндпоинт требует стабильный `x-opencode-session` для маршрутизации и кэша промптов — адаптер
добавляет его автоматически (один id на инстанс провайдера; можно переопределить через `headers`).

## Результат

- `GET https://opencode.ai/inference/v1/models` — HTTP 200, ключ валиден; в списке есть
  `deepseek-v4.1-flash`, `deepseek-v4.1-flash-free`, `deepseek-v4-pro`.
- Прямой `POST /inference/go/openai/v1/chat/completions` — HTTP 200, ответ на русском.
- Через адаптер `@opora/llm` (`chat`, streaming) — HTTP 200, SSE-чанки собираются, латентность
  первого теста ≈ 5,4 с (без стриминга на клиенте), модель вернула связный ответ.
- Тестовая реплика (синтетика, без ПДн): «Мне тревожно вечером, что можно сделать прямо сейчас?» —
  модель ответила спокойно, но дала список советов и обратилась на «вы». Для продукта нужен
  промпт-тюнинг (T-101): обращение «ты», один маленький шаг вместо списка, без советов-предписаний.

## Ограничения

- **Только синтетические данные.** Реальные переписки и записи дневника — специальная категория
  ПДн; отправка внешнему провайдеру требует трансграничной передачи (ст. 12 152-ФЗ) и не
  допускается до production-контура в РФ (D-010, D-023, ADR-0004).
- Ключ показан в чате при передаче — после тестов рекомендуется ротировать его в Console.
- Стоимость запросов списывается с Go-подписки/баланса основателя; в CI внешние вызовы не нужны
  (тесты работают на `fake` и локальном SSE-сервере).
