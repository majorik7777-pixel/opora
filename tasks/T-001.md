# T-001. Каркас репозитория и дизайн-система

- **Статус:** review
- **Owner:** lead
- **Приоритет:** P0
- **Оценка:** 1–2 дня
- **Зависимости:** —
- **Write-scope:** `package.json`, `pnpm-workspace.yaml`, `pnpm-lock.yaml` (только при необходимости), `.npmrc`, `.editorconfig`, `.gitignore`, `tsconfig.base.json`, `tsconfig.tools.json`, `eslint.config.mjs`, `apps/web/{package.json,next.config.ts,tsconfig.json,postcss.config.mjs,next-env.d.ts,public/**}`, `apps/web/src/app/{layout.tsx,globals.css}`, `apps/worker/**`, `packages/ui/**`, `packages/shared/**` (только интегратор), `packages/{core,db,llm}/package.json`, `packages/{core,db,llm}/tsconfig.json`, `scripts/setup-dev.mjs`
- **Ссылки:** [`docs/planning/12-tech-plan.md §1–2`](../docs/planning/12-tech-plan.md), [`10-design.md §3`](../docs/planning/10-design.md), [`06-decision-log.md`](../docs/planning/06-decision-log.md) (D-015), [`docs/adr/0001-stack-and-boundaries.md`](../docs/adr/0001-stack-and-boundaries.md)

## Цель

Создать pnpm-workspace каркас по ADR-0001 и дизайн-систему по `10-design.md`: строгий TypeScript, ESLint с проверкой границ слоёв, единый env из корня, токены и базовые компоненты `@opora/ui`, чтобы все следующие задачи ставились на готовую основу.

## Контекст

Phase 0–1 начинается с каркаса: репозиторий, пакеты, конфиги, дизайн-токены и компоненты. Фактические версии — `package.json`/lockfile (Next 15.5, React 19, TS 5.9, Tailwind 4, zod 4, Drizzle 0.45, PGlite 0.5). Границы слоёв и запреты импортов — ADR-0001. Дизайн — `10-design.md §3` (палитра, типографика Golos Text + Lora, сетка 8 pt, радиусы, тени).

## Scope

- Корень: workspace-конфиг, корневой `package.json` со скриптами (`dev`, `build`, `start`, `lint`, `typecheck`, `test`, `test:e2e`, `verify`, `db:generate`, `db:migrate`, `setup:dev`), `.npmrc` (локальные store/cache/state), `.editorconfig`, `.gitignore`, `tsconfig.base.json` (strict, `noUncheckedIndexedAccess`), `tsconfig.tools.json`.
- `apps/web`: package.json, `next.config.ts` (env из корня через `loadEnvConfig`, `transpilePackages`, `serverExternalPackages` для PGlite/pg/drizzle, security headers), tsconfig с alias `@/*`, postcss для Tailwind 4, self-hosted шрифты Golos Text и Lora, базовый `layout.tsx` и `globals.css` с токенами.
- `packages/ui`: дизайн-токены (CSS variables/классы), утилита `cn` (clsx + tailwind-merge), базовые компоненты по `10-design.md §5` (Button, Input, Textarea, Card и т. п. в объёме, достаточном для лендинга/онбординга), состояния default/hover/focus/disabled/loading.
- `packages/shared`: нижний слой — константы (`APP_NAME`, `PROGRAM_LENGTH_DAYS`, `FREE_MESSAGES_PER_DAY`, `CONSENT_VERSION`, `AUTH_TTL`, `ROUTES`, `RATE_LIMITS`), env-схема (zod), криптоутилиты (AES-256-GCM, sha256/HMAC, `randomToken`, `hashEmail`, `hashIp`), UUID v7, `ActionResult`/`ERROR_CODES`, схемы auth и онбординга; серверные утилиты — в `@opora/shared/server`.
- `packages/{core,db,llm}`, `apps/worker`: package.json/tsconfig-заготовки с правильными зависимостями и границами (реализация — в T-003/T-004/T-101).
- `eslint.config.mjs`: ESLint 9 flat config, `@typescript-eslint`, запрет `any`, правила `no-restricted-imports` для всех пакетов по таблице границ ADR-0001.
- `scripts/setup-dev.mjs`: создание корневого `.env` со случайными `AUTH_SECRET` и `ENCRYPTION_KEY` (права 600), идемпотентно; не перезаписывает существующий `.env`.

## Out of scope

- Лендинг, онбординг, auth, `/app` — T-002…T-005.
- Схема БД и миграции — T-003.
- E2E и CI — T-006.
- `.env.example`, `README.md`, `AGENTS.md`, ADR, `infra/` — документационный пакет (создаётся отдельно, сверить ссылки).
- Полный набор компонентов для чата/дневника/программы — соответствующие задачи.

## Acceptance criteria

- [ ] `pnpm install` с нуля проходит; `pnpm lint`, `pnpm typecheck` — без ошибок.
- [ ] Структура пакетов и их зависимости соответствуют ADR-0001; пакеты экспортируют TypeScript-исходники, Next транспилирует их (`transpilePackages`).
- [ ] Правила границ работают: импорт `react` в `packages/shared` или `drizzle-orm` в `apps/web` **роняет** `pnpm lint` (проверено на временном нарушении, затем убрано).
- [ ] Env читается из корня: Next не ищет `apps/web/.env`; `getEnv()` валидирует переменные и падает с понятным сообщением при неверном `ENCRYPTION_KEY`.
- [ ] `pnpm setup:dev` создаёт `.env` со случайными ключами и не перезаписывает существующий; ключи валидны для `packages/shared`.
- [ ] Дизайн-токены соответствуют `10-design.md` (палитра, шрифты Golos Text + Lora, размеры, радиусы, тени); компоненты `@opora/ui` используют только токены.
- [ ] Есть сквозные `ROUTES`, `COOKIE_NAMES`, `AUTH_TTL` как единый источник для страниц и auth.
- [ ] `pnpm build` собирает минимальное приложение (лендинг-заглушка) без ошибок.
- [ ] Обновлены `tasks/`, docs при решениях; новых решений сверх ADR-0001 нет (иначе — ADR/D-XXX).

## План работ

1. Workspace и корневые конфиги; `.npmrc`/`.gitignore`/`.editorconfig`.
2. `apps/web` и `packages/*` заготовки; tsconfig; ESLint-границы.
3. `packages/shared`: константы, env, crypto, uuid, api, схемы.
4. `packages/ui`: токены, `cn`, базовые компоненты; шрифты.
5. `scripts/setup-dev.mjs`; проверка `pnpm lint`, `pnpm typecheck`, `pnpm build`.

## Вопросы и допущения

- Версии зависимостей зафиксированы точно (без `^`) — осознанно, для воспроизводимости; обновление — отдельной задачей.
- Дизайн-система на Phase 0–1 минимальна: компоненты добавляются по мере экранов, но токены не меняются без решения.
- Tailwind 4 настраивается через CSS-first конфиг; JS-конфиг не используется, если не появится причина.
