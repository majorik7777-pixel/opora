# T-401. Проверка спроса до разработки программы

- **Статус:** planned
- **Owner:** основатель (шаги 1, 3, 4 — руками); шаг 1 может выполнить агент при наличии ключа Wordstat API
- **Приоритет:** P0
- **Оценка:** 3–4 недели (в основном ожидание данных теста)
- **Зависимости:** решения D-039, D-041, D-043 приняты; для шага 3 — минимальный лендинг со списком ожидания (не блокирует шаги 1–2)
- **Write-scope:** `docs/product/validation/**`, `tasks/T-401.md`
- **Ссылки:** D-013, D-019, D-039, D-041; `docs/product/positioning.md`; `docs/planning/05-audience-product.md` §8; аудит v4 §5

## Цель

Проверить, есть ли интерес к программе «Пережить расставание» и к формулировке «Опора», до сборки программы и до крупных трат на разработку. Результат — решение: идём дальше, меняем тему или меняем угол подачи.

## Контекст

- Интервью 10–15 женщин в одиночку невозможны. Проверка строится на открытых данных и простых замерах.
- Открытые данные уже есть: ВЦИОМ (2025) о потребности в психологической помощи; исследования переживания развода. Они описывают потребность, а не покупку конкретной программы.
- **Вордстат.** Старый интерфейс отключён, в новом нужен Яндекс-аккаунт. В рабочем окружении Hermes есть MCP-инструмент Wordstat (`top_requests`, `dynamics`, `regions_breakdown`), но ему нужен `YANDEX_SEARCH_API_KEY` в `~/.hermes/.env` — ключа сейчас нет. Если основатель даёт ключ, шаг 1 собирается агентом за час; иначе — вручную в веб-интерфейсе.
- Пороги из `05-audience-product.md` §8 — гипотезы автора документа, не проверенные данные. Используем как стартовые, пересматриваем после первого прогона.
- Тестовый контур закрыт `noindex` и работает на синтетике: конверсии лендинга измеряются только на отдельной странице со списком ожидания, не на основном домене.

## Scope

### Шаг 1. Вордстат (2–3 часа руками или 1 час агентом при ключе)
- 30 фраз по 5 темам: расставание, тревога, выгорание, самооценка, «не с кем поговорить».
- Фиксируем точную частотность (оператор `"!фраза"`) и динамику за 2 года, регион — Россия и Москва/СПб отдельно.
- Таблица: `docs/product/validation/wordstat-2026-11.md` с датой замера. Личных данных там нет по определению.

### Шаг 2. Открытые обсуждения (2–3 часа)
- Форумы, комментарии под публичными статьями, открытые группы.
- Выписываем формулировки боли своими словами (до 10 фраз на тему), без имён и ссылок на людей.
- Файл: `docs/product/validation/language-notes.md`. Цитаты только перефразированные.

### Шаг 3. Лендинг со списком ожидания (1–2 дня, после минимального макета)
- Одна страница: обещание (`positioning.md`), что внутри, что не делаем, паспорт данных, поле email, согласие на обработку.
- Без оплаты, без таймеров, без «осталось N мест». Формулировки — по правилам `docs/design/tz-redesign-v5.md` §4.
- Метрики: визиты, отправки формы, конверсия.

### Шаг 4. Тест Яндекс.Директа (20–25 тыс. ₽, 2–3 объявления)
- До запуска проверить правила Яндекса для рекламы психологических услуг и «ИИ-психолога».
- Одна ссылка на страницу ожидания, 2–3 темы объявлений (расставание; тревога; «не с кем поговорить»).
- Метрики: CTR, цена клика, конверсия в email, цена записи в список.

## Out of scope

- Интервью с людьми (не делаем).
- Оплата и депозит (нужна ЮKassa и оферта — T-104).
- Разработка программы и приложения.
- SEO-статьи (T-301…T-305, после решения).
- Тестирование цены (после первых продаж, D-007).
- Переделка основного лендинга (T-404…T-406) — здесь только страница ожидания.

## Пороги решения (предварительные, пересматриваем после шага 4)

| Показатель | Порог «продолжаем» | Порог «меняем» |
|---|---|---|
| Расставание в Вордстате по сравнению с другими темами | не ниже второй позиции по сумме точных частотностей | на последнем месте |
| Конверсия визит → email на странице ожидания | ≥ 15% (нижний ориентир) | < 5% за 300 визитов |
| Цена записи в список (Директ) | ≤ 300 ₽ | > 800 ₽ по всем темам |
| Конверсия клик → email | ≥ 3% | < 1% по всем темам |

Если расставание проигрывает другим темам по всем четырём показателям, меняем первую программу (D-039). Если проигрывает только по цене записи, меняем угол объявления, а не тему.

## Acceptance criteria

- [ ] `docs/product/validation/wordstat-2026-11.md` содержит 30 фраз, дату замера и регион.
- [ ] `docs/product/validation/language-notes.md` содержит не менее 10 перефразированных формулировок по каждой из 2 тем (расставание и «не с кем поговорить»); без персональных данных.
- [ ] Страница ожидания опубликована на тестовом домене с `noindex`; email шифруются по правилам ADR-0003, не хранятся в открытом виде.
- [ ] Директ-тест: бюджет не выше 25 000 ₽, отчёт с CTR, ценой клика и ценой записи по каждой теме.
- [ ] Итоговый отчёт `docs/product/validation/result.md`: данные, выводы, решение (продолжаем / меняем тему / меняем угол) и ссылка на D-XXX при изменении решения.
- [ ] Аналитика: события только обезличенные (AGENTS.md §8), без ПДн.
- [ ] Решение записано в журнал (`06-decision-log.md`).

## План работ

1. Вордстат: собрать таблицу, сохранить с датой замера.
2. Открытые обсуждения: выписать формулировки.
3. Страница ожидания (тексты — по `positioning.md`, визуал — по действующей системе).
4. Проверить правила Директа для тематики, запустить тест.
5. Подвести итоги по порогам, записать результат.

## Вопросы и допущения

- **Ключ Wordstat API.** Если основатель кладёт `YANDEX_SEARCH_API_KEY` в `~/.hermes/.env`, шаг 1 делает агент; иначе — руками. Это единственное, что блокирует автоматизацию шага 1.
- **Порог «не ниже второй позиции»** — допущение, пересмотреть после первого замера.
- **Страница ожидания без оплаты:** интерес без денег — достаточный сигнал на этом этапе. Если интерес есть, а контакт не оставляют, проблема может быть в доверии, а не в теме.
- **Кто ведёт тест Директа:** основатель. Нужна помощь с настройкой — отдельная задача.
