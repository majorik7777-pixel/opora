- **Оценка:** 2–3 дня
- **Зависимости:** T-003 (онбординг как контекст), T-004 (сессия/пользователь), T-005 (`/app`)
- **Write-scope:** `packages/llm/**`, `packages/core/src/chat/**`, `packages/core/src/safety/**` (только интерфейс хука), `packages/db/**` (таблицы чата и миграции — только интегратор), `packages/shared/src/chat.ts` (контракт — только интегратор), `apps/web/src/app/app/chat/**`, `apps/web/src/app/api/chat/**`, `apps/web/src/components/chat/**`, `docs/specs/chat.md`, `tests/**`
- **Ссылки:** [`docs/planning/09-product-spec.md §5`](../docs/planning/09-product-spec.md), [`12-tech-plan.md §6`](../docs/planning/12-tech-plan.md), [`07-architecture.md §6`](../docs/planning/07-architecture.md), [`11-copy.md §7`](../docs/planning/11-copy.md), D-010/D-021, [`docs/adr/0001-stack-and-boundaries.md`](../docs/adr/0001-stack-and-boundaries.md)

## Цель

Дать пользовательнице AI-собеседника с рамкой: потоковый ответ в чате, лимит 5 сообщений в день на free, минимум памяти (контекст онбординга и последние сообщения), вызов safety-хука до генерации. Провайдер LLM — за адаптером: сейчас `fake`, реальный провайдер РФ подключается конфигом.

## Контекст

Чат — вспомогательный слой продукта, а не «чат 24/7» (D-002). Персона и правила — `11-copy.md §7`: 3–5 предложений, один вопрос в конце, без осуждения, без диагнозов и лечения, при кризисе — остановка и экстренные контакты. Контекст собирается по `12-tech-plan.md §6.2`; домены не импортируют SDK провайдера (ADR-0001). Стриминг требует route handler/SSE — server actions для этого не подходят (ADR-0001).

## Scope

- `@opora/llm`: интерфейс `LlmProvider` (`chat(req) -> AsyncIterable<Chunk>`, `embed`, `moderate`), реестр провайдеров по `LLM_PROVIDER`, реализация `fake` (детерминированные потоковые ответы, учитывает системный промпт и историю), таймауты, 2 ретрая с джиттером, базовый circuit breaker, учёт токенов/стоимости без текста, реестр промптов (`chat.system.v1`).
- Контракт в `@opora/shared`: типы сообщений/ролей/чанков, схема лимита, коды ошибок (правит интегратор).
- `@opora/db`: `chat_threads` (один тред на пользователя в Phase 1), `messages` (`role`, `content_enc` AES-256-GCM, `tokens`, `safety_flag`, `provider`, `model`, `created_at`); миграции — интегратор.
- `@opora/core/chat`: создание треда, отправка сообщения (валидация → проверка лимита → safety-хук → сохранение user-сообщения → сборка контекста → стриминг ответа через адаптер → сохранение assistant-сообщения), подсчёт лимита 5/день (Europe/Moscow) с серверной проверкой, чтение истории.
- Сборка контекста (память минимум): системный промпт (`chat.system.v1`), ответы онбординга, последние 8 сообщений; бюджет токенов ≤ 2 500 с приоритетной обрезкой (`12-tech-plan.md §6.2`). Отдельная `memory_facts` и извлечение фактов — **не входит**, T-101 фиксирует точку расширения.
- Safety-хук: интерфейс `checkBeforeGeneration(text)`, вызывается до LLM; в T-101 — заглушка «риска нет», полные правила — T-105. Тест подтверждает, что хук вызывается.
- `apps/web`: `/app/chat` с потоковым UI (SSE/ReadableStream), пузыри, индикатор набора, «Осталось N сообщений сегодня», ошибки/повторы, быстрые действия из дизайна (`мне плохо сейчас` — подставляет фразу; остальные ведут в разделы).
- Тесты: unit (fake-провайдер, лимит, сборка контекста, шифрование), integration на PGlite (создание треда, сохранение/чтение, лимит), e2e (отправка → стриминг → ответ; лимит после 5; мобильный 360).
- `docs/specs/chat.md` — контракт домена: сообщения, лимиты, стриминг, контекст, safety-хук, ошибки.

## Out of scope

- Реальный провайдер РФ и ключи (адаптер готов, подключение — отдельным решением; в production-контуре РФ — D-010).
- Извлечение и хранение фактов памяти (`memory_facts`, «что AI помнит»), удаление/редактирование сообщений, несколько тредов, поиск по истории.
- Голос, транскрибация, вложения, картинки.
- Полный кризисный протокол и кризисный экран — T-105 (здесь только хук).
- Аналитика/события, напоминания, админка.
- Платный безлимит и токены — T-104 и позже.

## Acceptance criteria

- [ ] Ответ приходит потоком (не одним блоком после полной генерации) и отображается в UI по мере поступления; на `fake` ответ детерминирован в тестах.
- [ ] Лимит 5 сообщений/день проверяется на сервере; 6-е возвращает `RATE_LIMITED`, UI показывает «Осталось N сообщений сегодня» и понятное сообщение; на следующий день лимит сбрасывается (тест с подменой даты/часового пояса Europe/Moscow).
- [ ] Сообщения хранятся в БД зашифрованными (`content_enc`), текст не попадает в логи, ошибки и телеметрию.
- [ ] Контекст запроса содержит системный промпт, онбординг и последние сообщения; бюджет токенов ограничен; тест проверяет состав/обрезку.
- [ ] Safety-хук вызывается до генерации; при «риске» обычная генерация не запускается (поведение экрана — T-105, здесь проверяется остановка).
- [ ] Ответы соответствуют персоне: без диагнозов/лечения, без «всё к лучшему», с одним вопросом в конце (проверка в тестах промпта/фикстурах).
- [ ] Провайдер заменяется только `LLM_PROVIDER`; домены не импортируют SDK провайдера (лишний импорт роняет линт).
- [ ] UI: пустое состояние, индикатор набора, ошибка с повтором, мобильный 360 px, доступность (клавиатура, фокус, статусы для скринридера).
- [ ] `pnpm verify` и e2e проходят; `docs/specs/chat.md` создан и соответствует коду.
- [ ] При архитектурных изменениях (SSE-формат, схема таблиц) — ADR/D-XXX через интегратора.

## План работ

1. Контракты в `shared` и `llm` (интерфейс, fake, реестр, промпт).
2. Схема и репозитории чата; миграция (интегратор).
3. Сервис `core/chat`: лимит, контекст, safety-хук, сохранение; тесты.
4. SSE route handler и клиентский чат; быстрые действия.
5. E2E, мобильный 360, `docs/specs/chat.md`.

## Вопросы и допущения

- Один тред на пользователя в Phase 1 — упрощение; список тредов/удаление — позже.
- Лимит считается по user-сообщениям за календарный день в Europe/Moscow; точная таймзона пользователя — позже (в Phase 1 фиксированная).
- Память минимум = онбординг + последние 8 сообщений; факты и «что AI помнит» — отдельная задача после T-102.
- Пер-сообщение safety-хук в T-101 — заглушка; до T-105 нельзя открывать чат реальным пользователям.
